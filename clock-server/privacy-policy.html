Analog Clock ClockServer - Privacy Policy

Last updated: 10 September 2026

ClockServer is an internal development tool used by alpxstudio ("we") to build the Analog Clock widget. It is not a public product and is not distributed. It runs locally on our own computer and is reachable only from that computer. This policy covers ClockServer only; the Analog Clock Android app has its own policy.

Who uses it

Only us. The Google sign-in it offers exists so that we can grant the tool access to our own Google Ads account. No other person signs in to it, and there are no user accounts.

What it accesses

With your permission, ClockServer requests a single Google scope, https://www.googleapis.com/auth/adwords, and uses it to read advertising performance figures from the Google Ads account you authorise: campaign and ad names, ad images, impressions, clicks, conversions and cost. It reads only; it never creates, edits or pauses anything in the account.

It requests no other Google data - no Gmail, Drive, Contacts, Calendar, photos or profile information.

Where the data goes

  • The figures are displayed in the tool's own page on the local computer and cached there so the panel is not empty on the next run.
  • The refresh token returned by Google is written to a single local configuration file on that computer and is used only to renew access to the same account.
  • Nothing is uploaded anywhere. ClockServer has no backend, no database and no internet-facing address; it talks to Google's APIs and to nothing else.

Limited use

ClockServer's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements. The data is used only to display our own advertising results inside the tool. It is not shared with anyone, not sold, not used for advertising, and not used to train any model.

Retention and removal

The cached figures and the stored token live only on the local computer and are deleted by deleting those files. Access can be withdrawn at any time from Google Account permissions, which immediately invalidates the stored token.

Changes

If this policy changes, the date at the top will change with it.
